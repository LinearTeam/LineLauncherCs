# 项目名称使用政策 / Project Naming Policy

## 中文

### 适用范围

本政策由 LinearTeam 发布，针对 LineLauncher 项目的名称及对外展示方式。
本项目没有注册商标，本文件也不主张注册商标权。

本项目使用的名称包括：**LineLauncher、Line Launcher、LineLauncherCs、LMC**。
这些名称用于识别本项目，不表示本项目对通用词或缩写享有排他权。
特别是，本政策不限制无关项目在不造成混淆的情况下使用缩写 LMC。

官方源代码仓库：https://github.com/LinearTeam/LineLauncherCs

### 衍生项目的命名与展示

未经 LinearTeam 明确书面许可，独立修改版、衍生产品或服务的对外展示应遵守以下规则：

1. 使用独立的主要名称。不要将上述名称作为衍生产品的主要名称，或使用足以让用户误认为原项目、
   官方版本或官方关联项目的近似名称。仅添加 Pro、Plus、Enhanced、修改版等字样，
   不能代替清晰的独立命名和身份说明。
2. 不得通过产品名、安装包、应用商店条目、域名、页面设计或宣传内容，冒充原项目或暗示不存在的
   官方维护、授权、赞助或背书关系。不得以同样方式使用 LinearTeam、作者姓名或项目图标。
3. 对外发布独立修改版时，在 README、下载页或关于页等清楚可见的位置说明其修改者和非官方身份。
   说明必须符合实际关系；另行获得官方授权的发行版，以书面授权范围为准。

独立修改版可使用以下说明，并将维护者名称替换为实际名称：

> 本项目是基于 LineLauncherCs 的独立修改版，由 [维护者名称] 维护，
> 不是 LinearTeam 的官方发行版，也未获得 LinearTeam 的官方背书。

### 允许的来源说明

- 可以在版权声明、NOTICE、源码注释、致谢和其他来源说明中保留原项目名称，并链接官方仓库。
- 可以如实说明“基于 LineLauncherCs 修改”或描述兼容性，不得将来源说明包装成官方身份声明。
- 用于代码保存或协作的 GitHub fork 可以保留上游仓库名及平台的 fork 来源标记。
  不得将该仓库冒充为官方仓库；对外发布的衍生产品仍应使用独立名称。

不得以改名为由删除软件许可证要求保留的版权、署名和来源声明。

### 与开源许可证的关系

代码继续按 [Apache License 2.0](LICENSE.txt) 提供。
本文件是项目名称使用政策，不是额外的代码许可条件，不修改或撤销已授予的复制、修改和分发权利，
也不改变任何代码或资源原有的许可。必要的署名、NOTICE 复制和合理的来源说明不受本政策限制。

本文件本身不创设商标权或名称专有权。对造成混淆的行为是否可以采取法律措施，
取决于实际权利、使用方式及适用法律，而不是仅凭本文件。

如需使用原项目名称发布经授权的发行版，请通过官方仓库联系 LinearTeam，取得明确书面许可。

### Naming and Presentation of Derivatives

Unless LinearTeam expressly permits otherwise in writing, public presentations of independently modified versions,
derivative products, or services must follow these naming rules under this policy:

1. Use a distinct primary name. Do not use the names above as a derivative product's primary name, or use a similar
   name that is likely to cause confusion with the original project, an official release, or an officially affiliated
   project. Merely adding Pro, Plus, Enhanced, Modified, or similar wording does not replace distinct naming and
   a clear identification of the derivative.
2. Do not use product names, packages, store listings, domains, page designs, or promotional material to impersonate
   the original project or falsely imply official maintenance, authorization, sponsorship, or endorsement.
   Do not use LinearTeam's name, an author's name, or the project icon for those purposes.
3. When publishing an independently modified version, clearly identify its maintainer and unofficial status in
   a visible place, such as its README, download page, or About page. The statement must reflect the actual
   relationship. Separately authorized releases are governed by the scope of their written authorization.

An independent modification can use the following statement, replacing the maintainer name:

> This project is an independent modification of LineLauncherCs, maintained by [maintainer name].
> It is not an official LinearTeam release and is not officially endorsed by LinearTeam.

### Permitted Attribution

- You may retain the original project names in copyright notices, NOTICE files, source comments, acknowledgements,
  and other attribution, and link to the official repository.
- You may truthfully state that a project is based on LineLauncherCs or describe compatibility.
  Attribution must not be presented as a claim of official status.
- GitHub forks used to preserve code or collaborate may retain the upstream repository name and the platform's
  fork attribution. Do not present such a repository as the official repository; publicly released derivative
  products must still use a distinct name under this policy.

Renaming is not a reason to remove copyright, attribution, or origin notices required by the software's licenses.
